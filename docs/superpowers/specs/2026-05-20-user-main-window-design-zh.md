# 普通用户主界面设计

## 背景

`serialhelper-1.2` 当前启动后会直接进入完整的 Qt 控制窗口。这个窗口适合开发、调试和工程人员使用，但它暴露了串口配置、曲线、日志、TRY 扫描和底层激光控制等内容，普通用户日常操作不需要看到这些复杂控件。

新的启动体验应该是一个面向普通操作者的简洁主界面。现有完整窗口保留，但改为受密码保护的开发者界面。

## 目标

- 程序启动后显示新的普通用户主界面。
- 主界面只聚焦三个控件：
  - `L1 开/关（种子）`
  - `预放开/关`
  - `功率调整`，范围为 `2-100%`
- 采用已确认的“清爽工业风”：浅色背景、居中面板、大号蓝色控件、整体克制干净。
- 保留现有完整 `Widget` 开发者界面及其当前行为。
- 提供一个低调的 `开发者` 入口，只有密码验证通过后才打开旧的完整界面。

## 非目标

- 本任务不重新设计开发者界面。
- 本任务不升级串口协议。
- 本任务不修改 STM32 固件行为。
- 本任务不处理更大范围的安全加固。

## 架构方案

在 `serialhelper` Qt 工程中新增一个启动窗口类，暂定名为 `MainWindow` 或 `OperatorWindow`。`main.cpp` 不再直接显示现有 `Widget`，而是先实例化并显示新的普通用户主界面。

现有 `Widget` 保持为开发者窗口。普通用户主界面负责处理开发者入口：

1. 用户点击一个小号的 `开发者` 按钮。
2. 程序弹出密码输入框。
3. 密码正确时，隐藏普通用户主界面，并实例化或显示现有 `Widget`。
4. 密码错误或取消输入时，停留在普通用户主界面。
5. 开发者界面关闭后，重新显示普通用户主界面。

普通用户主界面应尽量在视觉和逻辑上与开发者界面解耦，后续给三个普通控件接入真实硬件控制时，不应打散现有开发者界面逻辑。

## 界面布局

普通用户主界面使用浅色应用背景，中间放置白色主面板。

面板内部包含：

- 标题，例如 `激光控制`。
- 三个纵向排列的大控件，宽度和高度保持一致。
- 前两个控件为开关类按钮，并能清楚显示当前开/关状态。
- 第三个控件为功率百分比输入，范围为 `2-100%`。
- 小号 `开发者` 按钮放在低强调位置，例如面板右下角。

视觉风格遵循已确认的 mockup 方案 A：

- 页面背景为浅灰或浅蓝灰。
- 主面板为白色，带轻微边框和阴影。
- 主按钮使用蓝色。
- 最终实现中圆角约为 8 px；如果 Qt 样式实际显示略大更自然，可以小幅调整。
- 中文字体优先使用 Windows 上显示稳定的微软雅黑，并设置合适 fallback。

## 行为

启动时：

- 显示普通用户主界面。
- 不自动显示开发者界面。

开发者入口：

- 点击 `开发者`。
- 弹出密码输入框。
- 密码正确时隐藏普通用户主界面，并打开现有 `Widget` 开发者界面。
- 密码错误时显示简短警告，并保持普通用户主界面不变。
- 关闭开发者界面后，自动回到普通用户主界面。

三个普通控件：

- `L1 开/关（种子）` 和 `预放开/关` 是面向 STM32 行为的普通操作控件。
- 第一版实现先完成界面、状态显示和开发者窗口密码入口，不凭空添加固件尚未支持的控制指令。
- `功率调整` 只接受 `2` 到 `100` 之间的整数百分比。
- 在把这三个控件真正接入硬件前，必须先明确串口命令映射。当前固件协议只定义了 `'0'~'9'` 激光步进命令，还没有定义种子开关、预放开关、功率百分比的直接指令。

## 错误处理

- 密码框取消：不改变任何状态。
- 密码错误：弹出警告框。
- 开发者窗口已经打开：普通用户主界面保持隐藏，将现有开发者窗口置前，而不是打开多个重复窗口。
- 功率输入越界：通过 Qt 数值控件限制，防止输入低于 `2%` 或高于 `100%`。

## 测试

需要手动验证：

- 程序启动后首先进入新的普通用户主界面。
- 普通界面视觉符合已确认的清爽工业风。
- 功率控件不能低于 `2%`，不能高于 `100%`。
- 取消密码输入后仍停留在普通用户主界面。
- 输入错误密码不会打开开发者界面。
- 输入正确密码会隐藏普通用户主界面，并打开现有开发者界面。
- 关闭开发者界面后，普通用户主界面会重新显示。
- 开发者界面已经打开时，再次点击开发者入口不会产生混乱的重复窗口。

## 密码策略

第一版实现使用一个硬编码的开发者密码常量：`laser2026`。

这对第一版本地桌面程序是可接受的，因为目标是避免普通操作者误入开发界面，而不是提供强账号安全。密码值应放在一个明显的常量位置，后续如果需要改密码，不应修改 UI 逻辑。
