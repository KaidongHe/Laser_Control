# MIR LASER 激光器控制系统 — main.c 逻辑说明文档

## 1. 系统概述

本程序运行于 STM32F103 微控制器，用于控制三路激光器（Laser1、Laser2、Laser3）的输出功率。系统通过 UART 串口接收单字符指令（`0`~`9`），调节各激光器的 DAC 输出电压，并通过 ADC 实时监测激光器的实际工作电压和电流。

---

## 2. 硬件资源分配

| 外设 | 用途 |
|------|------|
| **ADC1 + DMA** | 4 通道同步采样，监测 3 路激光器的电压与电流 |
| **内部 DAC** | 双通道输出，分别控制 Laser1（CH1）和 Laser2（CH2） |
| **I2C1 + MCP4725** | 外部 12 位 DAC，控制 Laser3（内部 DAC 通道不足） |
| **USART2** | 串口通信，接收上位机控制指令，输出状态信息 |
| **GPIO** | 激光器使能控制 + 温度状态读取 |

### GPIO 引脚分配

| 引脚 | 方向 | 功能 |
|------|------|------|
| PB12 | 输出 | Laser1 使能信号 |
| PB13 | 输入 | Laser1 温度状态（高电平=已就绪） |
| PA15 | 输出 | Laser2 使能信号 |
| PB14 | 输入 | Laser2 温度状态（高电平=已就绪） |
| PC4 | 输出 | Laser3 使能信号 |
| PB15 | 输入 | Laser3 温度状态（**当前已禁用检测**） |

### ADC 通道映射

| ADC 序号 | 对应引脚 | 测量对象 |
|----------|---------|---------|
| ADC_Value[0] | PA0 | Laser1 输出电流/电压 |
| ADC_Value[1] | PA1 | Laser2 输出电流/电压 |
| ADC_Value[2] | PA6 | Laser3 输出电压 |
| ADC_Value[3] | PA7 | Laser3 输出电流 |

---

## 3. 级联优先级使能机制

系统采用**级联依赖**的使能策略：高编号激光器必须在低编号激光器全部温度就绪后才能启用。

| 激光器 | 使能条件 | 使能引脚 |
|--------|---------|---------|
| **Laser1** | 自身温度就绪（`temp_status_prev1 == 1`） | PB12 |
| **Laser2** | Laser1 **且** Laser2 温度均就绪 | PA15 |
| **Laser3** | Laser1、Laser2 **且** Laser3 温度均就绪 | PC4 |

### 核心函数

- `CheckLaser1Priority()` — 返回 `temp_status_prev1`（仅检查自身）
- `CheckLaser2Priority()` — 返回 `temp_status_prev1 && temp_status_prev2`
- `CheckLaser3Priority()` — 返回 `temp_status_prev1 && temp_status_prev2 && temp_status_prev3`
- `UpdateLaserEnableStatus()` — 根据优先级结果刷新三个激光器的硬件使能引脚

> **注意**：Laser3 的温度检测已被注释禁用，`temp_status_prev3` 在初始化时被硬编码为 `1`，因此只要 Laser1 和 Laser2 就绪，Laser3 即可启用。

---

## 4. 温度监测（防抖机制）

主循环中每隔 `TEMP_DEBOUNCE_MS`（200ms）轮询一次温度引脚状态：

```
PB13 → Laser1 温度
PB14 → Laser2 温度
PB15 → Laser3 温度（已禁用）
```

当检测到温度状态变化时：
1. 更新对应的 `temp_status_prev` 标志
2. 通过串口打印状态变更信息
3. 调用 `UpdateLaserEnableStatus()` 重新评估所有激光器的使能状态

---

## 5. 串口指令集

系统以**非阻塞方式**接收单字节指令（100ms 超时），指令字符与功能对应如下：

### Laser1 控制（指令 `0` ~ `3`）

| 指令 | 功能 | 步长 | DAC 范围 |
|------|------|------|---------|
| `0` | 粗调减小 | -31 | 0 ~ 3103 |
| `1` | 粗调增大 | +31 | 0 ~ 3103 |
| `2` | 细调减小 | -3 | 0 ~ 3103 |
| `3` | 细调增大 | +3 | 0 ~ 3103 |

- DAC 上限 3103 ≈ 2.5V 输出（满量程 4095 ≈ 3.3V）
- 控制电流计算公式：`Ic = DAC × 3.3 / 4096 / 2.5`

### Laser2 控制（指令 `4` ~ `7`）

| 指令 | 功能 | 步长 | DAC 范围 |
|------|------|------|---------|
| `4` | 粗调增大 | +31 | 0 ~ 3103 |
| `5` | 粗调减小 | -31 | 0 ~ 3103 |
| `6` | 细调增大 | +3 | 0 ~ 3103 |
| `7` | 细调减小 | -3 | 0 ~ 3103 |

- 计算公式与 Laser1 相同
- 注意指令 `4`/`5` 的增减方向与 Laser1 的 `0`/`1` 相反

### Laser3 控制（指令 `8` ~ `9`）

| 指令 | 功能 | 步长 | DAC 范围 |
|------|------|------|---------|
| `8` | 增大 | +20 | 0 ~ 1861 |
| `9` | 减小 | -20 | 0 ~ 1861 |

- DAC 上限 1861 ≈ 1.5V 输出
- 使用外部 MCP4725 DAC（I2C 接口），非内部 DAC
- 控制电流计算公式：`Ic = DAC × 3.3 / 4096 × 6.13`

---

## 6. 指令执行流程

每条有效指令的处理流程一致：

```
1. 检查对应激光器的优先级使能条件
   └─ 不满足 → 打印错误信息 → 跳过
2. 根据指令字符更新 DAC_Value（带边界限幅）
3. 将 DAC 值写入硬件（内部 DAC 或 MCP4725）
4. 延时等待电压稳定（Laser1/2: 100ms，Laser3: 200ms）
5. 强制刷新 ADC DMA 采样
6. 计算并打印状态信息（DAC值、控制电流、输出电压/电流）
7. 清零 uart_cmd，避免重复执行
```

---

## 7. Laser3 特殊处理

Laser3 与其他两路有多处不同：

| 特性 | Laser1 / Laser2 | Laser3 |
|------|----------------|--------|
| DAC 类型 | STM32 内部 DAC | 外部 MCP4725（I2C） |
| 稳定延时 | 100ms | 200ms |
| ADC 转换 | 线性比例 | 自定义线性映射函数 |
| 温度检测 | 正常轮询 GPIO | **已禁用，恒为就绪** |
| DAC 上限 | 3103（2.5V） | 1861（1.5V） |

### Laser3 专用转换函数

- `Laser3_ADCtoVoltage()` — 将 PA6 的 ADC 电压（0~3.26V）线性映射到实际电压（2.0V~3.3V）
- `Laser3_ADCtoCurrent()` — 将 PA7 的 ADC 电压（0~2.71V）线性映射到实际电流（0.8A~10A）

---

## 8. ADC 采样机制

- 使用 **ADC1 + DMA** 连续采样 4 个通道
- 在每次 DAC 调整后，调用 `UpdateADCValues()` 强制刷新：
  1. 停止当前 DMA 传输
  2. 清零 `ADC_Value[]` 数组
  3. 重新启动 DMA 传输
  4. 等待 50ms 确保转换完成
- ADC 转换完成中断回调 `HAL_ADC_ConvCpltCallback` 会打印原始 ADC 数据（用于调试）

## 10. 系统时钟配置

- 时钟源：外部高速晶振（HSE）+ PLL 9 倍频 → **72MHz 系统时钟**
- APB1：36MHz（HCLK/2）
- APB2：72MHz（HCLK/1）
- ADC 时钟：PCLK2/6 = 12MHz
- Flash 延迟：2 个等待周期

## 12. 安全保护机制

1. **温度联锁**：激光器必须在温度就绪后才能启动，且采用级联依赖
2. **DAC 限幅**：每次调节均有上下限限幅，防止输出超出安全范围
3. **指令单次执行**：处理后立即清零 `uart_cmd`，防止同一指令重复触发
4. **超时保护**：串口接收 100ms 超时后自动清零指令，避免卡死
5. **使能状态联动**：温度状态变化时自动更新硬件使能引脚，异常时硬件级关断

## 13. 已知问题 / 待完善项

- **Laser3 温度检测已禁用**（代码中被注释），当前恒返回"就绪"状态，实际硬件保护依赖 Laser1 和 Laser2 的级联条件
- **指令 `4`/`5` 增减方向与 Laser1 相反**，可能造成操作混淆，建议统一
- **ADC DMA 刷新方式**：每次调用 `UpdateADCValues()` 都会停止并重启 DMA，频繁操作时效率较低，可考虑使用连续模式 + 双缓冲
- 系统主循环使用 `continue` 跳过无效数据，若串口持续收到噪声可能造成看门狗复位风险（当前未启用 IWDG）
